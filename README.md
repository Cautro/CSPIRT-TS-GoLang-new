# CSPIRT

Backend школьной социальной рейтинговой системы (School Social Rating System) на Go. Сервис ведёт учёт пользователей (учеников, учителей, администрации), классов и параллелей, рейтинга учеников, заметок, жалоб, расписания, школьных и общешкольных ("global") событий с квизами, а также push-уведомлений через Firebase Cloud Messaging.

## Стек

- **Язык:** Go 1.25
- **HTTP-фреймворк:** [Gin](https://github.com/gin-gonic/gin)
- **База данных:** PostgreSQL (доступ через `pgx/v5`, драйвер `database/sql`)
- **Кэш / rate-limit / blacklist токенов:** Redis (`go-redis/v9`), опционален — при недоступности отключается с предупреждением в лог
- **Аутентификация:** JWT (`golang-jwt/jwt/v5`) + cookie-based refresh-токены
- **Push-уведомления:** Firebase Cloud Messaging (`firebase.google.com/go/v4`)
- **Логирование:** структурное, на базе `log/slog`
- **Профилирование запросов:** встроенный middleware с разбивкой по времени и статистикой пула соединений БД

## Архитектура

Проект построен по слоистой (layered) архитектуре, близкой к Clean Architecture:

```
cmd/app                 — точка входа (main.go): сборка зависимостей и запуск сервера
internal/
  domain/               — доменные сущности, ошибки и интерфейсы репозиториев по каждому модулю
    user/ class/ note/ complaint/ event/ rating/ schedule/ globalEvent/ cache/
  usecase/              — бизнес-логика поверх доменных интерфейсов (auth, user, class, note, complaint, event, rating, schedule, globalEvent, notification)
  adapter/
    postgres/           — реализации репозиториев поверх PostgreSQL, инициализация storage
    redis/               — клиент и кэш-репозиторий на Redis
    config/              — загрузка конфигурации из окружения
  controller/
    http/                — HTTP-хендлеры (Gin) и роутинг по модулям
    permission/           — проверка прав доступа (ролевая модель)
    utils/                — общие утилиты контроллеров (middleware авторизации и т.п.)
pkg/
  httpserver/, logger/, postgres/, profiler/, redis/ — переиспользуемые инфраструктурные пакеты
```

Модули домена: `auth`, `user`, `class` (в т.ч. параллели/четверти/учебный год), `rating`, `note`, `complaint`, `event`, `globalEvent`, `schedule`.

## Возможности API

Все маршруты, кроме `/health`, `/login` и `/api/refresh`, требуют JWT-авторизации (`/api/...`, middleware проверяет токен и, при доступном Redis, — blacklist/rate-limit).

- **Auth:** логин, обновление токена, логаут, регистрация/отмена push-устройств
- **Users:** список пользователей, персонал, добавление/удаление, профиль (`/me`), обновление данных и аватара
- **Classes:** классы, параллели, привязка классов к параллели, назначение классного руководителя, завершение четверти/учебного года
- **Rating:** получение и обновление рейтинга учеников
- **Notes / Complaints:** заметки и жалобы на пользователей с учётом прав доступа
- **Events:** события класса с параметрами
- **Global Events:** общешкольные события — информационные и квизы (с голосованием)
- **Schedule:** расписание, перенос (rollover) и сброс плановых расписаний

Полный список маршрутов — в `internal/controller/http/router.go`.

## Конфигурация

Настройки читаются из переменных окружения (см. `.env.example`), при старте подгружается `.env` через `godotenv`, если файл присутствует.

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `JWT_SECRET` | секрет для подписи JWT (обязателен) | — |
| `DB_PATH` | строка подключения к Postgres | `data/storage.db` |
| `PORT` | адрес, на котором слушает сервер | `:8080` |
| `COOKIE_SECURE` | флаг `Secure` для cookie | — |
| `SEED_TEST_USERS` | засеять тестовых пользователей при старте (`1`/`0`) | `0` |
| `PARALLELS` | конфигурация параллелей вида `"1-4,5-9,10-11"` | — |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` / `REDIS_DB` | подключение к Redis (кэш, rate-limit, blacklist токенов) | `localhost` / `6379` / — / `0` |
| `PROFILE` | включает middleware профилирования запросов (`1`/`0`) | — |

Также требуется файл `firebase-credentials.json` в корне проекта для инициализации FCM (при его отсутствии сервис уведомлений просто не поднимается, приложение продолжает работать).

## Запуск

```bash
# 1. Скопировать и заполнить конфигурацию
cp .env.example .env

# 2. Поднять зависимости (Postgres/Redis) и применить схему из cspirt_full.sql к базе

# 3. Установить зависимости и собрать
go mod download
go build -o cspirt ./cmd/app

# 4. Запустить
./cspirt
```

Проверка живости: `GET /health`.

## Деплой

Деплой в продакшн автоматизирован через GitHub Actions (`.github/workflows/deploy.yml`): сборка Go-бинаря, остановка `systemd`-сервиса `cspirt.service` на сервере, копирование бинаря по SCP и повторный запуск сервиса.
